# DS Lite 鸿蒙外壳（本地 React + ArkWeb）

本目录是仓库内的 HarmonyOS 工程：原生 HAP 外壳通过 Web 组件加载随包打包的 DS-Lite React 前端，复用原有聊天、记忆与 API 调用逻辑，不做全量 ArkUI 重写。

当前状态：最小端到端混合包已在本机完成 **unsigned debug HAP** 编译。本地更新分支已快进到上游默认分支（含原作者已合并的鸿蒙 PR #1，以及上游网页前端至 0.9.30；上游安卓安装包仍为 0.9.29）。真机安装、AI 流式、持久化与系统分享均不能仅凭编译成功视为已可用。维护者其后口头反馈在本机 DevEco 本地模拟器上基本可用，这是**用户报告**，不是本仓库的独立复测。

## 已核实的原项目技术结构

以下结论来自仓库源码，不是外部方案的照搬：

- 前端：React 18 + TypeScript + Rspack，状态 Zustand；无 react-router，单页应用。
- 构建：`publicPath: 'auto'`，相对资源在虚拟 HTTPS 源下可解析。
- 无自建后端。默认请求 `https://api.deepseek.com`（`__API_ORIGIN__`），用户也可在设置里填写自定义源（需实现 DeepSeek 兼容接口并允许 CORS）。
- AI 流式：浏览器 `fetch` POST，`Accept: text/event-stream`，用 `ReadableStream` 解析 SSE，不是 EventSource。
- 持久化：IndexedDB（`idb`，库名 `chat-demo`）存对话与文件；localStorage 存设置、角色卡等；壁纸大图在单独 IndexedDB。API Key 存在 localStorage（`chat-demo:api-key`）。
- Android：Capacitor 8 封装。`@capacitor/filesystem` 与 `@capacitor/share` 仅用于导出保存/系统分享（`src/services/export/saveFile.ts`）。自定义 `SharedArchive` 插件用于 Android 传入的压缩包，在非原生平台为 no-op。文件选择走页面里的 `<input type="file">`。
- Service Worker 只在 `https` 或 `127.0.0.1` 注册，`localhost` 跳过。鸿蒙外壳使用虚拟 `https` 源，因此前端在检测到 `__DS_LITE_PLATFORM__ === 'harmonyos'` 时跳过 SW，同步资源时也不打包 `sw.js`。

## 已实现

- 独立构建脚本 `pnpm build:harmonyos`：先走现有生产构建 `scripts/build.mjs`，再把 `dist` 同步到 `entry/src/main/resources/rawfile/web/`。默认 `pnpm build`、Web、Android 行为不改。
- 首页改为 ArkWeb `Web` 组件。按官方做法使用虚拟 HTTPS 源 `https://ds-lite.invalid/`（RFC 2606 保留的 `.invalid`，避免与公网域名冲突），在 `onInterceptRequest` 中只拦截该主机，把路径映射到包内 `rawfile/web`。`https://api.deepseek.com` 及用户自定义 API 源返回 `null`，走真实网络，不拦截。
- `javaScriptAccess(true)`、`domStorageAccess(true)`；`fileAccess(false)`；`geolocationAccess(false)`；`mixedMode(MixedMode.None)`。未处理 `onSslErrorEvent`，不关闭证书校验，不放宽 CORS 或混合内容。网页权限请求默认拒绝。
- 在文档开始前向该虚拟源注入 `window.__DS_LITE_PLATFORM__ = 'harmonyos'`（`scriptRules` 仅限该源）。
- 声明普通权限 `ohos.permission.INTERNET`。
- 最小导出/分享桥 `window.DsLiteHarmony`：只暴露 `beginExport` / `appendExport` / `cancelExport` / `finishExport`。校验调用帧 URL 必须属于 `https://ds-lite.invalid`，并用官方 JavaScriptProxy permission 白名单限制同源。只接受文件名（清洗路径分隔符与控制字符），只写入应用缓存 `cacheDir/dslite-exports/`，不提供任意读本机文件的接口，不把文件内容或 API Key 写入日志。分享使用官方 `systemShare` + `fileUri.getUriFromPath`。若分享面板未能打开，前端会收到明确错误，不把失败说成成功。
- Android 的 Capacitor 导出/分享路径保持原样；鸿蒙不伪装 `Capacitor.isNativePlatform()`。`SharedArchive` 在鸿蒙上仍为 no-op（暂不支持从系统分享/打开传入压缩包）。
- 应用显示名改为「DS Lite」。`EntryAbility` 在 `onCreate` 中调用 `webview.WebviewController.initializeWebEngine()`。

## 明确不支持或未做

- 未做全量 ArkUI 重写，未自建后端，未把 UI 托管到远端。
- 未签名、未发布、未提交、未推送，未连接真机或模拟器 GUI。
- 未关闭证书校验或 CORS，未加调试用的任意原生桥。
- 鸿蒙侧暂不接入 Android 的 `SharedArchive` 传入分享。
- 系统分享依赖 Share Kit，编译时提示部分设备类型（如部分车机/手表/电视）不具备该系统能力；这些设备上分享会失败并如实报错。分享是否能在手机/平板上拉起，仍待真机验证。
- 导出体积上限约 80 MB；超过会失败并报错。
- `<input type="file">` 导入、`<a download>` 降级下载是否在 ArkWeb 可用，未验证。桥未覆盖导入。

## 本地打开工程

用 DevEco Studio 打开目录 `harmonyos`。目标 SDK / compatible SDK 为 HarmonyOS `26.0.0`（API 26）。bundleName：`com.dslite.harmonyos`。

重新打包前请先在仓库根目录执行 `pnpm build:harmonyos`，确保 `rawfile/web` 为最新前端资源。

## 安全说明

- 桥只服务随包前端的虚拟源，不向任意网页开放危险原生能力。
- 不读取调用方传入的本地路径，不记录或传出 API Key。
- 不要在本工程里关闭 TLS 校验或放宽 CORS 来“绕过”直连限制；这类限制只能在真机上验证并记录。
